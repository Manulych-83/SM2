# Checkpoint 1 — текущее состояние отдельно от истории

13 сентября 2026. Пользователь подтвердил следующий шаг после Foundation 3.

## Контракт

Основная кампания получает отдельный формат контрольной точки. Декодер проверяет текущее состояние по действующим каталогам и инвариантам, без воспроизведения всех прошлых команд. Старый Survival 3 сначала полностью проверяется повторением команд и исходов через прежние правила и сравнением итогового мира, затем переводится в новый формат в памяти. Публикация — только при явном сохранении; прежний файл остаётся резервной копией. Исторические режимы остаются прежними.

Выбрана доверенная локальная контрольная точка: проверка состояния и целостности файлов, а не доказательство происхождения каждого XP повторным исполнением истории. Хеш не является подписью и не защищает от сознательного редактирования всех согласованных данных. Диагностический повтор старой истории остаётся отдельным путём. Эта граница гарантии явная и не меняет правила получения опыта.

История записывается ограниченными неизменяемыми блоками, адресуемыми хешем. Снимок содержит ссылки и текущие данные; блоки публикуются раньше снимка. Неуспешная запись может оставить невостребованный блок, но не должна портить прежнюю рабочую кампанию. Блоки, на которые ссылаются старые снимки/.bak, не удаляются. Очистка архива — отдельная работа.

Журнал и поход получают факты на принятых переходах, без выдачи наград из UI. Завершение похода фиксируется однажды; более раннее сохранение имеет более ранний результат. Последний бой и активная встреча сохраняют необходимый контекст. Смерть, новое тело, анатомия, предметы, знания, модификации и практика остаются прежними.

## Приёмка

- Короткий полный путь: бой, поиск, перенос, доставка, сохранение/загрузка и журнал; отдельные смерть/новое тело и активный бой.
- Старый слот остаётся пригодным до публикации нового, .bak восстанавливается; отказ загрузки не меняет живую сессию.
- Повреждённое состояние, неизвестные ID, неверные тела/владельцы, несовместимый контент, повреждённый/отсутствующий блок и отказ записи отклоняются.
- Старая тестовая история 4096 и новая история больше 4096: равное состояние, факты, страницы истории; новое сохранение/загрузка целятся в ≤3 с, чтение цели ≤100 мс на текущем ПК. Первое преобразование старого формата может быть медленным.
- Все проверки/слоты/сборки внутри SM2. Механики не расширять, пользовательские сохранения не использовать, коммит/публикация отдельно. Перед этапом 5 остаётся ручной просмотр.

## Реализованные границы

Версия приложения **0.8.23-checkpoint.1**, основная сессия `sm2.checkpoint_journey.1`, блок `sm2.history_block.1`. Мир внутри остаётся `sm2.world.survival.3`, активный бой сохраняет действующую схему. Имена трёх слотов прежние, блоки находятся рядом в `history_blocks/<sha256>.json`. Переносить резервную копию нужно вместе с этим каталогом; один корневой JSON нового формата не содержит полного архива.

- `Sm2CheckpointWorld`: явное восстановление тел, Души, инвентаря, анатомии, развития, региона и припасов. Проверяются каталоги, роли, владельцы, допустимость воплощений и общая последовательность выдачи ID предметам/воплощениям. Затем применяются существующие проверки мира. Это проверка согласованного состояния, а не повтор всех причин, приведших к нему.
- `Sm2CheckpointSession`: отдельная основная сессия поверх прежних команд/боевого settlement. Все переходы проходят через кандидата; текущие факты и запись истории публикуются вместе с миром. Загрузка использует отдельного кандидата и не запускает ходы/восстановление ресурса/награды.
- `Sm2CheckpointArchive`: до 64 записей в блоке; исход боя закрывает блок сразу. Ограничение дерева файла может закрыть блок раньше. Последний закрытый бой и его исходный мир хранятся отдельно для прежнего экрана результатов и поля боя; обрезание служебной короткой истории их не теряет.
- `Sm2HistoryRepository`: неизменяемые файлы с проверкой содержимого и точных записанных байтов до публикации; существующий повреждённый блок не перезаписывается. Кэш разбора проверяется SHA256 **всего файла** при каждом повторном чтении. Размер/время изменения не используются как доказательство неизменности. Корневой файл и `.bak` обслуживает прежний `Sm2CampaignStore` с семантической проверкой.
- `Sm2CheckpointFacts`: накопленные факты похода и зафиксированный первый итог. Представления цели/журнала не повторяют команды. После JSON-загрузки целые значения нормализуются, чтобы номера жизней и XP не отображались с `.0`. Навигация экрана последнего боя по-прежнему использует текущее тело/место/ревизию; исторические потери и опыт остаются прежними.

Проверяются **все** блоки при холодной загрузке, без симуляции истории. Журнал получает все подготовленные строки и использует прежние страницы по 30. Ленивого чтения только видимой страницы с диска пока нет; стоимость загрузки всё ещё зависит от размера архива. В памяти закрытые блоки разделяются между кандидатами, а данные, выдаваемые UI, отделяются копированием.

Инженерный потолок архива — 65536 записей; прежние ограничения размера/вложенности отдельного файла сохраняются и могут сработать раньше. Фактически нагрузочно проверены 4160 настоящих переходов; это не приёмка 65536 боёв, огромного мира или тысяч карточек развития. Удаление слота не очищает общие блоки: безопасная сборка невостребованных файлов ещё не сделана. Аппаратная атомарность при отключении питания не обещается.

Каталоги, формулы, XP, характеристики, способности, боевые правила и правила получения вещей в этом срезе не изменены. Большие каталоги/выборки UI остаются следующим пунктом фундамента.
