# Creatures 1 — шаблоны существ и встречи

13 сентября 2026. **0.8.35-creatures.1**. Первый рабочий срез пункта 3 [плана масштабирования](CONTENT_SCALING_PLAN.md), внутри этапа 3 общего плана. После Sequences 1 пользователь подтвердил реализацию шаблонов существ и встреч.

## Разделение определений и экземпляров

`Sm2CreatureCatalog` хранит три группы: профили параметров, шаблоны типов и встречи. Профиль связывает параметры очереди и боя с существующим `body_id`. Шаблон ссылается на профиль, снаряжение, доступные действия со статусами, иммунитеты, сопротивления, внешний вид и поддержанную политику ИИ. Оружейные действия выдаются существующим снаряжением. Встреча задаёт поле, seed, предел раундов и список размещений: ID экземпляра, ID типа, сторону, управление и координаты.

Одно определение налётчика может использоваться несколькими участниками. У них общие неизменные параметры и набор снаряжения, но независимые ID участников, ID экземпляров предметов, здоровье, прочность, боеприпасы, состояния и действия. Повреждение экземпляра не меняет шаблон. Главный герой основной кампании не получает уровневую модель врагов из этого примера.

Каталог индексирует типы, параметры и встречи по ID. Сборка проверяет весь авторский набор один раз, включая неиспользуемые профили и ссылки, с помощью существующих каталогов очереди/снаряжения/статусов. Ошибка не заменяет прежний каталог. Публичные определения возвращают защитные копии. Списки по ID и размещения по ID участника нормализуются; семантический порядок шагов составной способности остаётся прежним.

`compile(encounter_id)` выбирает только типы и профили этой встречи. Из них создаются обычные каталоги и setup для существующего боевого ядра. Для пяти участников примера достаточно четырёх типов и трёх профилей; 3000 записей исходного каталога не становятся 3000 участниками или 3000 боевыми комплектами. Комплект определяется хешем ID типа, одинаковым для всех его экземпляров. Боевые ID предметов по-прежнему назначает движок при создании участников.

Общие определения предметов, тел и операций из исходных небольших каталогов пока сохраняются в компилируемом наборе целиком. Адресное сокращение этих зависимостей при совместных больших каталогах — отдельная дальнейшая работа.

## Авторинг и пределы

`content/packages/creatures.json` использует уже существующий загрузчик пакетов. `content/creatures/catalog.json` содержит профили, типы и встречи. Новая комбинация поддержанных параметров/экипировки/действий добавляется данными, без ветки кода по ID врага. Неизвестная возможность отклоняется; запись в шаблоне сама по себе не создаёт механику.

Версия — `sm2.creatures.1`. До 3000 типов, до 3000 профилей и до 1000 встреч; 2–64 участника во встрече, две стороны. Размещения проверяются на повтор ID/клетки, границы и проходимость. В этом срезе `company` управляется игроком, `opposition` — ИИ. Общие ограничения пакетов и файлов сохраняются: до 10000 строк выбранных групп и 8 МиБ на файл.

ИИ использует существующую политику `sm2.ai.abilities.1`, которая понимает оружие, поддержанные статусы и составные воздействия. Различные наборы действий дают разные доступные решения. Другие `behavior_id` пока отклоняются: несколько личностей/политик одновременно в одном бою не реализованы.

`body_id` пока ссылается на прежний боевой профиль зон body/head. Пример использует человеческое тело. Это не перенос тканей/органов основного похода и не реализация животных, многоруких существ или новых рас. Полная анатомия основного похода продолжает работать по своему прежнему контракту.

## Рабочие встречи и интерфейс

Четыре авторских типа: страж, налётчик, следопыт и отравитель. Страж получает очищение с прикрытием; отравитель — ослабление с ядом и иммунитет к яду. HP в примере различается: 80 / 55 / 45 в соответствующих профилях. Это технические параметры, не окончательный баланс или новые знания героя.

В дополнительных режимах есть **«Патруль: двое против троих»** и **«Дозор: двое против одного»**. Отдельного кода для их состава нет. Список формируется из каталога, до 12 строк на странице. Интерфейс показывает имена и фактические параметры через `Sm2CreatureBattleRunner.view`; названия типов не вычисляются по строке комплектов. Палитра условных фигур задана отдельно в `content/presentation/creatures.json`, цвет стороны и выбор цели сохраняются. Изменение внешнего вида не влияет на расчёт боя.

## Сохранение и совместимость

Шаблонный исполнитель использует существующий снимок эффектов schema5 и обычный формат исполнителя, отдельное хранилище `user://creature_encounters/<sha256 ID встречи>`. При загрузке дополнительно проверяет принадлежность участников шаблонам, исходным сторонам/управлению и исходной встрече/полю. Названия и оформление восстанавливаются как представление; они не добавляются в изменяемый снимок боя.

Fingerprint компилируемого каталога включает версию, весь авторский каталог, поля, зависимости и ID встречи. Изменение определения, даже не участвующего во встрече, пока требует новой игры этого режима. Проверки fingerprint не отключены. Это строгая первая схема, не миграция произвольных изменений контента. Нормализация чисел JSON при проверке поля обязательна: целые числа после чтения файла могут быть представлены как float.

Сохранение, продолжение ИИ и повтор команд используют прежние механизмы. Боевые правила не переопределяются в новом исполнителе; он связывает экземпляры с типами и даёт представление интерфейсу.

## Что остаётся по пункту 3

В основном походе `JourneyWorld` по-прежнему связывает встречи с заранее созданными телами, фиксированными участниками героя/спутника и историей мира. `Sm2EncounterFactory` этого пути ещё использует общий профиль бойца. Подмена его шаблонным компилятором без изменения происхождения тел/вещей и сохранений была бы неполной интеграцией.

Следующий срез — связать шаблоны с постоянными телами, полноценной анатомией и результатами встречи, версионировать новый мир и определить совместимость прежних походов. Далее — оставшаяся совместимость пакетов и общая нагрузочная приёмка всех четырёх больших каталогов. Перед этапом 5 общего плана необходим ручной просмотр пользователя и согласование замечаний.
