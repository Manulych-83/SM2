Весь журнал через диагностический старый API теперь дороже из-за обращения к репозиторию; обычный экран использует постраничный запрос. Это различие не скрыто за сравнением разных API.

Проверка архива новым репозиторием сама по себе занимает около 1 с; полное открытие новым сервисом замеряется позже, когда файловый кэш ОС уже прогрет. «Без кэша сервиса» не означает холодного диска. Здесь время **повторного сохранения**, а не первая публикация всех блоков. Прогоны частично пересекались с тестами; это диагностические одиночные замеры, не статистическое сравнение изолированного ПК. Все итоговые проверки стенда прошли, код 0.

Прежний стенд Checkpoint 1 также повторён без ослабления порогов: `outputs/runtime-2/compatibility-scale`, код 0, `passed=true`, `performance_passed=true`. Полный перенос старых 4096 команд — 72,660 с; после ещё 64 настоящих переходов первая запись 65 блоков — 1,739 с, загрузка через общий валидатор стенда — 0,425 с, открытие новым сервисом кампаний — 1,403 с, получение всего журнала — 58,020 мс, цель — 0,963 мс. Совпадение мира/истории и дискового снимка проверено. Однократное преобразование старого формата остаётся медленным; этот путь пока не оптимизирован.

## Рост инвентаря и развития

Отдельная нагрузка: 100/1000/10000 корректных предметов, один сундук на каждые 10 записей, остальные предметы помещены в него. Используются реальные определения `stash`/`medical_kit`, прежний декодер и проверка точного результата. До изменения инвентаря — `stress-baseline`, после — `verified`.

| Предметы / контейнеры | Проверка до | Проверка после |
| --- | ---: | ---: |
| 100 / 10 | 5,378 мс | 2,007 мс |
| 1000 / 100 | 226,178 мс | 19,568 мс |
| 10000 / 1000 | 23671,970 мс | 226,443 мс |

Выявленный повтор обхода всех предметов на каждый контейнер устранён. Копирование инвентаря из 10000 предметов после изменения — 17,931 мс. Это fixture модели инвентаря, не сохранение полноценного большого мира.

Развитие: существующая схема, каталоги 100/1000 узлов, опыт начислен существующей функцией, узлы куплены в порядке предпосылок с проверкой каждой покупки. Декодирование тела с 1000 изученными узлами — 53,245 мс, проекция направлений — 6,189 мс. Эти операции в данном этапе не оптимизированы; нагрузка обозначает следующий участок роста. В предварительном `stress-before` был ошибочный ID предмета `medicine`, стенд корректно завершился кодом 1; эти времена отказа не используются как производительность инвентаря.
