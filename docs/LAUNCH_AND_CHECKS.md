# Запуск, проверки и сборка SM2

## Путь героя P4.1

Двойной щелчок по `E:\GPT\SM2\Запустить игру.cmd`, затем «Путь героя». Вещи можно снимать, надевать, передавать и класть в тайник только вне боя. Три встречи используют текущие здоровье, развитие и снаряжение. Пустой слот оружия даёт удар кулаком. После воплощения вещи нужно забрать из мира. Для продолжения — «Сохранить», затем при новом запуске «Продолжить путь». Лечение и ремонт здесь ещё не реализованы.

Отдельный слот: `user://journey/p4_journey.json`. Пользовательский runtime не использовать для тестов. Проверки нового ядра: `tools/run_checks.ps1 -RuntimeRoot .local/p4_1/test-runtime -Suite p4_journey`. UI: `tools/run_ui_checks.ps1 -RuntimeRoot .local/p4_1/ui-runtime -OutputDirectory outputs/p4_1/ui-new -Suite p4`; каждый запуск UI требует нового OutputDirectory. `-Headless` проверяет обработчики без визуальной приёмки. Общая проверка — Suite all; старые режимы сохраняют свои слоты.

## Мир и воплощение P3

«Запустить игру.cmd» → «Мир и воплощение». До боя можно положить камень в тайник. Пройдите сражение, затем вернитесь в локацию через «Меню» на поле. Доступны упражнения, узлы и «Завершить жизнь тела…» с подтверждением. Выберите обычного человека и заберите тот же камень. Если герой погиб в бою, после исхода сразу доступен выбор тела.

«Сохранить» записывает весь мир вместе с боем; после перезапуска нажмите «Продолжить» рядом с «Мир и воплощение». Слот .local/runtime/appdata/SM2/world/p3_world.json независим от прежних режимов. В примере одна встреча: новое воплощение не создаёт её заново.

Проверки ядра: tools/run_checks.ps1 -Suite p3_world -RuntimeRoot .local/checks/p3. UI: tools/run_ui_checks.ps1 -Suite p3 -RuntimeRoot .local/checks/p3-ui -OutputDirectory outputs/p3/manual-ui. Используйте свежие каталоги, отдельно от пользовательского запуска. Результаты — STATUS_P3.md.

## Развитие в настоящем бою P2

Версия 0.5.2-p2: «Запустить игру.cmd» → «Бой с развитием». Управляйте героем и спутником, атакуйте мечом, смотрите опыт через «Развитие». Узлы покупаются после завершения боя. «Сохранить» записывает бой и оба тела вместе; после перезапуска — «Продолжить» рядом с новым режимом.

Слот: .local/runtime/appdata/SM2/development/p2_development_run.json. Ядро: tools/run_checks.ps1 -Suite p2_development -RuntimeRoot .local/checks/p2. UI: tools/run_ui_checks.ps1 -Suite p2 -RuntimeRoot .local/checks/p2-ui -OutputDirectory outputs/p2/manual-ui. Для нового отчёта нужен свежий каталог. -Headless проверяет контракты, исключая отрисовку. Результаты — [STATUS_P2.md](STATUS_P2.md).

## Лаборатория развития P1

В версии 0.5.1-p1: «Запустить игру.cmd» → «Лаборатория развития». Четыре упражнения мечом дают уровни силы 11 и ближнего боя 2. Изучение узлов расходует опыт своего направления, сохраняя уровень и продвижение. Для продолжения после перезапуска откройте лабораторию и нажмите «Загрузить».

Слот через CMD: .local/runtime/appdata/SM2/progression/p1_lab.json. Старые боевые слоты отдельны. Проверочный набор ядра — tools/run_checks.ps1 -Suite p1_progression -RuntimeRoot .local/checks/p1. Интерфейс — tools/run_ui_checks.ps1 -Suite p1 -RuntimeRoot .local/checks/p1-ui -OutputDirectory outputs/p1/manual-ui. Ключ -Headless исключает визуальную приёмку. Фактические результаты и ограничения — [STATUS_P1.md](STATUS_P1.md).

## Обычный запуск

Дважды щёлкните `E:\GPT\SM2\Запустить игру.cmd`. Файл находит проект относительно собственного расположения, подготавливает ресурсы и запускает окно игры. Рабочая папка Windows не влияет на поиск проекта. Вспомогательное окно PowerShell скрыто; при ошибке появляется сообщение с путём к журналу.

В текущей версии выберите «Начать сражение»: доступен бой 3 на 3 с управлением мышью, прогнозом, ИИ, журналом и исходом. «Сохранить» записывает бой, «Продолжить бой» загружает его после перезапуска. Прежний экран отряда M1 также сохранён. Подготовка ресурсов и автоматические проверки сами по себе не подтверждают удобство интерфейса — окно игры проверяется отдельно.

## Где находится Godot

Нужен стандартный Godot **4.7.2 stable**. На этом компьютере основной файл установлен здесь:

```text
C:\Users\Alexandr\AppData\Local\Microsoft\WinGet\Packages\GodotEngine.GodotEngine_Microsoft.Winget.Source_8wekyb3d8bbwe\Godot_v4.7.2-stable_win64.exe
```

Скрипты ищут движок в таком порядке:

1. Параметр `-GodotPath`, если он указан.
2. Файл `E:\GPT\SM2\.local\godot.path`.
3. Переменная среды `GODOT_BIN`.
4. Установка WinGet и доступные команды `godot` / `godot4` в `PATH`.

Файл `godot.path` — обычный текстовый файл UTF-8 с одним путём к EXE. Можно скопировать в него путь выше. Версия проверяется перед работой. Если заданный вручную путь неверен, скрипт сообщает об ошибке. Движок и шаблоны автоматически не скачиваются.

Запуск и экспорт не удаляют сохранения. Проверки хранилища используют отдельные каталоги `user://tests`, по умолчанию внутри `.local\test-runtime\appdata\SM2\tests`. Кнопка «Сохранить отряд» обновляет единственный пользовательский слот; создание нового отряда требует отдельного нажатия этой кнопки для записи. Прикладная сессия M2 использует слот `m2_prototype`, отдельно от M1 `session`; к текущему игровому экрану она ещё не подключена.

Уже запущенная игра сохраняет прежнее окружение до ручного перезапуска. Старые данные из обычного `%APPDATA%\SM2` автоматически не переносятся и не удаляются.

## Автоматические проверки

Обычный способ — двойной щелчок по **«Проверить проект.cmd»**. По окончании появится сообщение с результатом и расположением отчёта.

Для запуска из PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_checks.ps1" -Suite all
```

Доступны наборы `all`, `unit`, `integration`, `scenario`, `spatial`, `m2_content`, `m2_movement`, `turn_scheduler`, `turn_content`, `m2_snapshot`, `m2_turns`, `m2_turn_storage`, `m2_attacks`, `m2_combat_storage`. Перед проверками выполняется импорт проекта. Успех требует завершения Godot без ошибок, нового отчёта с `passed=true`, положительного целого числа проверок и пустого списка ошибок. Отсутствующий отчёт или ноль проверок успехом не считаются. Код завершения скрипта: `0` при успехе, `1` при ошибке. Начиная с M2.1 проверочный RuntimeRoot по умолчанию — `.local/test-runtime`, отдельно от игрового `.local/runtime`.

Подготовка проекта без открытия окна игры:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_game.ps1" -PrepareOnly
```

Все основные скрипты принимают `-GodotPath "полный путь к Godot.exe"`. Для технического запуска игры предусмотрены также `-NoDialogs` и массив `-ExtraArguments`; они нужны автоматизации, а для обычного запуска достаточно CMD-файла.

Для изоляции у скриптов запуска, проверки, экспорта и прогона поля есть `-RuntimeRoot`: абсолютный путь внутри проекта либо путь относительно его папки. Выход за пределы проекта и символические ссылки в этом пути запрещены. Например:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_checks.ps1" -Suite all -RuntimeRoot ".local\checks\isolated-runtime"
```

Пространственный прогон M2.1 выполняется через `tools/run_field_demo.ps1` с RuntimeRoot по умолчанию `.local/field-demo-runtime`. Он перемещает участника по трём клеткам настоящими командами и создаёт JSON-отчёт в `.local/logs`. Это диагностический запуск без игрового окна; полный бой и его интерфейс реализованы последующими M2.5 и M3. В уже изолированном внешнем окружении, где автоматический поиск установленного Godot не срабатывает, передайте его проверенный полный путь через `-GodotPath`.

Этот запуск получает собственные `appdata`, `cache` и `temp`. Для чистой копии проекта путь также должен находиться внутри этой копии.

Прогон очереди M2.2:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_turn_demo.ps1"
```

Используется `.local/turn-demo-runtime`. На основной карте лучник делает шаг, откладывает ход, возвращается после остальных, сохраняется и загружается. Восьмая команда завершает ход и начинает раунд 2. Следующие события и полный снимок сравниваются с непрерывной сессией. Журнал и JSON — `.local/logs/turn-demo-*`. Ожидаются код0, `passed`, `save_reload_equal`, `continuation_equal`, `m1_slot_unchanged` = true. Это проверка симуляции и дискового сохранения без окна боя.

## Прогон атаки M2.3

Прогон атаки M2.3:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_attack_demo.ps1"
```

Три небольших сценария используют авторские предметы на сближенных позициях: удар мечом, разрушение активного щита и выстрел. Всего девять принятых команд. Каждый сценарий записывает состояние на диск и сравнивает продолжение после загрузки с непрерывной сессией. Боевые сохранения M2.3 имеют собственный формат; очередь M2.2 в них автоматически не преобразуется.

## Прогон последствий M2.4

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_consequence_demo.ps1"
```

Три сценария, восемь команд: реакция останавливает шаг, следующий отход и escape заканчивают бой; паника снимает защиту щитом после Wait; последний удар выигрывает бой до лимита раундов. Начальные повреждения/мораль специальных сценариев явно указаны в initial, команды записаны отдельно. Перед каждой командой выполняется настоящее сохранение/загрузка и сравнивается продолжение. Результат законченного боя записывается один раз, в том числе после перезапуска. Проверяются признаки save_reload_equal/continuation_equal/m1_slot_unchanged и код0.

Данные — `.local/consequence-demo-runtime`, JSON и журнал — `.local/logs/consequence-demo-*`. Можно задать собственный RuntimeRoot внутри проекта и явный GodotPath. В `run_checks.ps1` добавлены suites `m2_consequences` и `m2_consequence_storage`. Это программная проверка ядра без игрового окна; текущий CMD по-прежнему открывает стартовый экран.

## Полный бой M2.5

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_battle_demo.ps1"
```

Три полных боя 3 на 3 на авторской карте, с seed20260909/1/76 и явным управлением ИИ обеими сторонами. После12 команд — сохранение и загрузка. Продолжение, новый прогон с начала и воспроизведение записанных команд без ИИ должны совпасть. Для каждого сценария проверяются save_reload_equal, continuation_equal, fresh_replay_equal, command_replay_equal, result_recorded_once, m1_slot_unchanged; код процесса0. В штатных боях повторных попыток команд быть не должно.

RuntimeRoot по умолчанию `.local/battle-demo-runtime`, отчёт и журнал `.local/logs/battle-demo-*`. Поддерживаются явный GodotPath и отдельный RuntimeRoot внутри проекта. Отчёт содержит исходную карту/профиль/снимки и весь журнал. `run_checks.ps1 -Suite m2_ai` запускает проверки ИИ и исполнителя, `-Suite all` — весь проект. Пользовательские слоты не используются; исполнитель сохраняется в m2_ai_run только в своём тестовом каталоге.

Это программный бой без игрового окна. Игровое поле M3 доступно через «Запустить игру.cmd» → «Начать сражение».

## Отдельный EXE

Для экспорта нужен установленный Windows release-шаблон Godot **4.7.2 stable**. Скрипт копирует только `windows_release_x86_64.exe` в кеш шаблонов выбранного `RuntimeRoot` и проверяет SHA256. Установленный шаблон остаётся на месте, скачивания нет. При заданном `custom_template/release` используется этот путь. Команда:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\export_game.ps1"
```

При успешном экспорте создаётся `E:\GPT\SM2\builds\SM2.exe`: Windows x86_64, игровой пакет встроен в EXE. Повторный экспорт обновляет этот файл. Тесты, инструменты разработки, документация и локальные журналы исключены из игрового пакета; определения контента включены.

**Прямой запуск EXE пока использует стандартный `%APPDATA%\SM2`**, поскольку обходит локальное окружение CMD/PowerShell. Для текущей разработки с данными внутри `E:\GPT\SM2` используйте **«Запустить игру.cmd»**.

Сам факт создания EXE не подтверждает, что все игровые действия проверены: после сборки нужно отдельно открыть её, создать отряд, сохранить, закрыть и продолжить сохранение.


## Игровой экран M3

Бой имеет отдельный файл `.local/runtime/appdata/SM2/battles/m2_ai_run.json` (и .bak при повторном сохранении). Сохранение отменяет оставшиеся шаги маршрута и записывает уже достигнутое состояние. «Вернуться на поле» продолжает бой из памяти, «Продолжить бой» читает диск. Новый бой не перезаписывает сохранение автоматически.

Синие — отряд, красные — враги. Наведение показывает прогноз; щелчок по свободному подсвеченному гексу — движение, по врагу — атака. Специальные способности выбираются снизу. Правая кнопка отменяет остаток пути/выбор; выполненные команды не отменяются. ИИ ходит автоматически. «Ждать» откладывает активацию, «Конец хода» завершает её.

Отдельная проверка интерфейса с отрисовкой:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_ui_checks.ps1"
```

Создаются свежие `.local/ui-checks/<timestamp>` и `.local/ui-reports/<timestamp>`. Можно явно передать RuntimeRoot и OutputDirectory внутри проекта. `-Headless` проверяет только программные контракты M3 без кадров; `-Suite m1` проверяет прежний экран отряда с отрисовкой. Чистый импорт выполняется перед тестовым скриптом. Нативная проверка мышью и ограничения — в STATUS_M3.md.

## Эффекты M4.1

Слот через рекомендуемый CMD: `.local/runtime/appdata/SM2/effects/m4_effects_run.json`. Старые каталоги отряда и боя не используются новым примером. Ожидание и загрузка не вызывают тик.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_checks.ps1" -Suite m4_effects -RuntimeRoot ".local\checks\m4-effects"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_ui_checks.ps1" -Suite m4
```

Для M4 также доступен `-Headless`, но он не подтверждает внешний вид. Реальные результаты и границы проверки — в [STATUS_M4_1.md](STATUS_M4_1.md).

## Мана и заклинание M4.2

«Бой с магией» добавляет к эффектам запас маны и «Магическую стрелу». Цена — 4 AP, 6 усталости и 8 маны; дальность 1–4 с общей линией видимости. Запас 24, восстановление +4 в начале раунда. Прогноз показывает уже уменьшенный сопротивлением урон HP. Щит и броня его не поглощают.

Слот через CMD: `.local/runtime/appdata/SM2/magic/m4_magic_run.json`. После перезапуска — «Продолжить бой с магией». Старые слоты остаются отдельными.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_checks.ps1" -Suite m4_magic -RuntimeRoot ".local\checks\m4-magic"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\GPT\SM2\tools\run_ui_checks.ps1" -Suite m4_magic
```

Набор m4_magic включает полный бой на авторской карте с первым заклинанием игрока, последующей диагностической самоигрой, дисковым продолжением и повтором команд. Это не новая политика магии для ИИ. Результаты — [STATUS_M4_2.md](STATUS_M4_2.md).

## Области M4.4

Нажмите «Бой по области», выберите «Чародейский взрыв» и наведите на центральную клетку. Фиолетовый контур показывает область, красный — поражаемых противников. Урон по своим отключён. Щелчок применяет заклинание, правая кнопка отменяет выбор. Цена: 5 AP, 10 усталости, 12 маны. Для продолжения сохранённого боя — «Продолжить бой по области».

Слот через CMD: .local/runtime/appdata/SM2/areas/m4_area_run.json. Специальные проверки: tools/run_checks.ps1 -Suite m4_areas с отдельным RuntimeRoot; tools/run_ui_checks.ps1 -Suite m4_areas с отдельным RuntimeRoot и OutputDirectory. Ключ -Headless проверяет контракты без отрисовки. Фактическая приёмка — STATUS_M4_4.md.
