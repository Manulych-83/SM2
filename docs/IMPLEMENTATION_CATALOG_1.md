# Catalog 1 — пакеты физических предметов

Версия 0.8.31-catalog.1. Первый рабочий пункт [утверждённого плана](CONTENT_SCALING_PLAN.md). Изменения подключены к действующему загрузчику Survival, а не оставлены отдельной лабораторией.

## Пакеты

`content/packages/survival.json` задаёт format `sm2.content_packages.1` и пакеты base → devices → repair → tissues. Корень выбирает существующий профиль кампании. `Sm2ContentPackages` проверяет все описания пакетов, пропавшие зависимости и циклы итеративно; читает только источники выбранных пакетов и их зависимостей. Независимые пакеты упорядочены порядком манифеста, зависимые — после предпосылок. Порядок строк исходного файла сохраняется.

Источник содержит group, path и field: пустой field означает корневой массив JSON. Только JSON под `res://content/`, без переходов к родителю; один файл не больше 8 МиБ. До 1000 пакетов, 1000 источников на пакет, 10000 строк суммарно в выбранном наборе. Это предел первого загрузчика, не готовая политика всех четырёх будущих каталогов вместе.

Опциональный integer_fields задаёт поля, требующие целого числового значения: дробь, bool, строка и отсутствующее значение отклоняются. Он сохраняет прежний тип чисел ремонтного комплекта после переноса его определения из кода в JSON. Область допустимых игровых значений по-прежнему проверяет доменный каталог.

Повтор ID внутри группы запрещён, включая одинаковые определения: нет неявного перекрытия последним файлом. Ошибка указывает пакет, путь и ID; для дубля — оба источника. Успешный результат содержит происхождение каждой записи. Компиляция возвращает отдельные данные без изменения источников. Разрешение пакетов не заменяет проверки предметов, устройств, ресурсов и связи с боевой экипировкой; после компиляции выполняются прежние проверки SurvivalContentLoader и SurvivalCatalog.

Чтобы добавить разновидность предмета с существующими свойствами, можно добавить запись в действующий файл либо добавить источник items к выбранному пакету. Отдельный пакет включают через requires выбранного корня; скрытых автоматических подключений файлов нет. Новый боевой предмет также должен иметь согласованные определения в боевом каталоге: Catalog 1 пока не объединяет эти схемы и не создаёт новое поведение из имени предмета.

## Индексы и совместимость

SurvivalCatalog хранит индексы предметов, частей и устройств и ленивую контрольную сумму. Проверка дублей предметов использует множество вместо растущего массива. Индексы публикуются только после успешной проверки всего каталога; отказ rebuild сохраняет прежние определения и хеш. Успешная пересборка заменяет индексы и сбрасывает хеш. Публичные item/device/to_data возвращают отдельные копии.

Предел физических определений расширен с 1000 до 10000. Форматы и остальные правила прежние. Каталоги всех трёх профилей и journey_fingerprint сопоставляются с записанными до изменения значениями; порядок и числовые типы прежние. Это гарантирует совместимость данной перестройки с прежним контентом, но не произвольных будущих изменений контента со старыми сохранениями.

## Авторская проверка

`tools/check_content.ps1` проверяет действующую кампанию, пакеты предметов, ссылки и развитие. В report.json добавлены число определений, выбранные пакеты и происхождение записей. `-ItemManifestFile content/packages/survival.json` позволяет проверить другой манифест, сохраняя все проверки реальной кампании. Он должен поддерживать корень survival.tissues. Нельзя совместить с ProgressionFile. Самостоятельные JSON-пакеты не обходят доменную проверку.

## Оставшиеся ограничения

Пакеты пока подключены только к предметам. Навыки/статусы/существа, независимые версии пакетов и миграции сохранений, общие операции и возможности — следующие срезы. Сохраняются ограничения человеческой анатомии, известных ID первых примеров и двух врагов встречи. Полный мир/инвентарь всё ещё копируется; UI не принят на 10000 разных вещей. Пределы сохранений и физического количества экземпляров не увеличены. Снятие лимита каталога не означает, что обычный профиль кампании сохранит 10000 экземпляров в прежнем структурном бюджете.
