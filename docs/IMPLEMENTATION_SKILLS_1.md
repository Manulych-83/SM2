# Skills 1 — 5000 самостоятельных навыков

Версия 0.8.32-skills.1, продолжение [CONTENT_SCALING_PLAN.md](CONTENT_SCALING_PLAN.md). Поддержка большого числа направлений, их практики, междисциплинарных условий, хранения и экрана развития. Новые игровые механики и художественный контент не добавлялись.

## Пакеты развития

Основная цепочка HybridContentLoader подключает `content/packages/progression.json`, корень `progression.main`. Пакеты расширяют уже собранное развитие кампании, а не заменяют исторические загрузчики старых режимов. Поставляемый корень пуст: текущие определения, их порядок и fingerprint сохраняются. Добавление источников/зависимостей этого корня позволяет вводить новые направления без изменения загрузчика.

Группы расширений: tracks, nodes, activities, contributions, knowledge. Вклад между направлениями в авторском пакете имеет дополнительный уникальный id; после проверки пакета он удаляется из доменного представления, где прежняя идентичность связи — source/target. Повторы определений относительно базового контента, неверные ссылки и циклы отклоняет ProgressCatalog. Источники ошибок пакетов сохраняют пакет/путь/ID.

Для большого набора отдельная группа profile содержит одну строку `{"id":"progression","version":"sm2.progression.large.1"}`. В этом уже существующем LARGE-профиле пределы tracks, nodes, activities и contributions расширены до 10000 на группу; knowledge остаётся до 1000. Прочие версии сохраняют пределы. Это поддержка 5000 навыков плюс характеристики, не 5000 активных боевых способностей. Лимиты схем псионических/гибридных способностей и таблицы боевых наград этим этапом не меняются.

ProgressPackageLoader запрашивает у общего компилятора бюджет 40000 строк суммарно. Авторский JSON сам не задаёт этот бюджет; физические пакеты предметов по умолчанию остаются на 10000. Выбор групп и доменные проверки не заменяются свободной интерпретацией JSON.

Пример записи практики использует прежнюю схему awards как массив: `[{"track_id":"my:skill.example","amount":10}]`. Операции и условия остаются существующими. В частности, обычная лагерная практика доступна после первой встречи; новая схема не обходит это правило. Боевые/анатомические требования для новых разновидностей определяются соответствующими каталогами, а не именем навыка.

Авторская проверка: `tools/check_content.ps1 -ProgressionManifestFile content/packages/progression.json`. Проверяется расширенный каталог и его связка с действующим развитием/боем. Флаг несовместим с другими входами проверки. Отчёт отдельно считает навыки, характеристики, занятия и узлы.

## Адресные запросы

Существующий ProgressRules.track читает только выбранное направление и непосредственные вклады; нет транзитивного суммирования. Новый индекс activities_for_track выдаёт только занятия, дающие опыт выбранному направлению. Индекс пересоздаётся при успешной сборке каталога.

Экран передаёт compact_tracks: для поиска и фильтра получает имена/ID/категории, без расчёта всех уровней и прибавок. Полная выбранная карточка и до 24 видимых строк рассчитываются адресно. Узлы/связи сохраняют прежние страницы. Общий application-запрос без compact_tracks сохраняет прежний полный результат для старых клиентов. Поиск по именам всё ещё проходит метаданные; это не обход всех правил развития. Источники боевой/исследовательской практики остаются отдельными существующими запросами.

## Хранение тела

Для LARGE-каталога с более чем 1000 направлениями новые тела используют явную маркировку `track_layout=sm2.body_tracks.sparse.1`. В tracks записываются только направления с опытом, оплатой или узлами. Отсутствующее направление означает нулевую практику; исходный уровень берётся из определения. В памяти тело пока по-прежнему имеет все направления — это оптимизация сериализации, не разреженное хранение всей симуляции.

Декодер восстанавливает нулевые направления и полностью проверяет ID, числовые типы/границы, сортировку, дубликаты, оплату из нескольких направлений и предпосылки. Явные нулевые строки в sparse запрещены ради единственного представления. Неизвестный layout и попытка выбрать sparse для обычного каталога отклоняются. Полная прежняя форма также принимается и сохраняет свою форму при копировании/загрузке. Малые и прежние LARGE/200-направлений примеры не меняют сериализацию. Быстрый сертификат монотонного XP не принимает новую форму, она проходит полный декодер; боевой профиль действует после проверки как прежде.

Пределы файла 8 МиБ, структурных значений LARGE 200000, коллекции 10000 и глубины 32 сохранены. Файл не выбирает политику каталога/бюджета. Внутреннее копирование полного мира и всех направлений в памяти остаётся расходом.

## Приёмка и границы

Синтетический набор: 5000 навыков + 8 характеристик, несколько тысяч занятий, узлов и вкладов; перекрёстная покупка из двух отдельных запасов XP. Проверяется герой с практикой во всех направлениях, реальное отступление из первой встречи, обычная тренировка после неё, покупка, следующий бой, итоги и сохранение/загрузка через действующую сессию. Подготовка широкой практики в стенде синтетическая, не выдаётся за 5000 реально сыгранных занятий.

UI проверяется на 2560×1440 и 1280×720: страницы, поиск дальнего навыка, реальные команды покупки и сохранения. Старые UI/форматы проходят отдельные регрессии. [Фактические отчёты](STATUS_SKILLS_1.md).

Это не одновременная приёмка 10000 предметов, 2000 статусов и 3000 типов врагов. Не доказаны огромный мир, массовая отрисовка лагерных занятий, все навыки со всеми изученными узлами сразу, модификации контента между версиями и мгновенные файловые операции. Общие условия/модификаторы/составные эффекты и последующие пункты плана остаются следующими срезами. Ручной просмотр перед этапом 5 обязателен.
