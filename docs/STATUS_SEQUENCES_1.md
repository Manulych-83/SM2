Новый набор проверяет неверные ссылки/операции/поля/политику, пустую и слишком длинную последовательности, неизвестные факты и неверные типы условия, атомарность неудачной сборки и защитную копию вложенных данных. Старые определения пересобираются с прежним hash и не получают поля steps.

Боевые проверки: общая цена 3 ОД, одна ревизия, порядок событий и два новых ID; условие видит первый применённый статус; промах не бросается и RNG не меняется. Иммунитет с skip оставляет ослабление, с reject отклоняет всё. Проверены false-условие обоих режимов, полные сроки/полный no-op, обновление обоих сроков без новых ID, ограничения стороны/ресурсов. При одном оставшемся ID для двух шагов команда отклоняется без изменений; при двух проходит. ИИ учитывает ту же границу. 62 старых эффекта + 2 новых помещаются в 64, 63 + 2 отклоняют целый корень.

Очищение с прикрытием выполняется по порядку. Переименованный вариант «наложить → снять → наложить» работает без изменения кода и использует новый ID при повторном наложении. Цепочка из 16 листьев завершается с ожидаемым порядком и восемью выделениями ID. Отдельно построен каталог из **2000 определений**, выполнено реальное действие и точное восстановление снимка: в активном состоянии остаются только два применённых экземпляра, прогноз и события совпадают с малым каталогом.

ИИ в подготовленной ситуации выбирает сочетание ослабления и яда, повторное решение совпадает и не меняет исходный бой. **Полный бой с шестью участниками** завершается до предельного раунда; составные действия действительно использованы, повторных попыток после отказа команды нет. Продолжение после сохранения даёт те же решения и события; повтор всей истории командами воспроизводит конечный снимок. Прежний набор ИИ дополнительно проходит свои бои с магией/эффектами на трёх seed.

Все UI-наборы rendered=true. Проверены реальные события мыши с физическими координатами при масштабе QHD и 1280×720: вход в дополнительный режим, выбор способности, прогноз обоих шагов и иммунитета, применение, запись и загрузка, продолжение через новый объект исполнителя. Старый дополнительный слот не создаётся новым режимом. Просмотрены [QHD-прогноз](../outputs/sequences-1/ui-final/sequence-2560.png) и [поддержка 1280×720](../outputs/sequences-1/ui-final/support-1280.png): шаги видны в начале панели, подробности прокручиваются. Основной боевой интерфейс и прежний пример эффектов проходят свои проверки.

Первый запуск нового теста выявил ошибку самой заготовки: `fatigue_max` читался из снимка, где этот параметр берётся из каталога и не хранится. Исправлено чтение из существующего view, игровые правила и ожидаемый отказ при недостатке сил не менялись. Итоговый набор выполнен полностью.

## Локальное измерение

[measure.json](../outputs/sequences-1/measure.json): по пять серий из 1000 двухшаговых прогнозов, оба каталога заранее в памяти, прогрев, чередование порядка. Два участника, без исходных активных эффектов; построение каталога не входит в замер.

| Определений | Медиана 1000 прогнозов | Разброс серий |
|---|---:|---:|
| 3 | 595,51 мс | 432,52–916,02 мс |
| 2000 | 903,61 мс | 434,84–981,56 мс |

Получено примерно **0,43–0,98 мс на прогноз** в этих сериях. Разброс существенный; точный коэффициент зависимости от размера каталога из такого замера не выводим и ускорение не заявляем. Первоначальный последовательный замер сохранён отдельно в `measure-sequential.json`; итоговый стенд изменён для чередования порядка и одинакового присутствия обоих каталогов в памяти. Это не нагрузочная приёмка 2000 одновременно действующих эффектов, большого боя, сохранений или всех четырёх целевых каталогов вместе.
