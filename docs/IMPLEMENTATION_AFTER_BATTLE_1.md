# After Battle 1 — рост после завершения сражения

13 сентября 2026. **0.8.29-after-battle.1**. Прямой запрос пользователя: во время боя накапливать опыт, повышение характеристик/навыков перенести на конец, показать таблицу роста.

## Правило

В новых боях основной checkpoint-кампании собственная практика и изученные узлы героя остаются на начальных значениях до завершения сражения. У спутника аналогично фиксируются общий опыт и уровень. Все боевые расчёты — попадание, пси-импульс, щит, гибридные способности — продолжают читать это тело. Временные эффекты, раны, состояние снаряжения, усталость, концентрация и позиция остаются динамическими.

Прежние источники и величины XP сохранены: личные выполненные действия, попадания, промахи и реакции; у героя отдельные направления, у спутника общий опыт. Во время боя меняются только счётчики действий и производные суммы накопленной практики. Уровни при накоплении не вычисляются.

При любом завершении боя, включая отступление, поражение и предел раундов, после всех действий/реакций/последствий закрывающей команды практика применяется один раз на её изолированном кандидате, до проверки и публикации результата. Закрывающий удар использует прежний уровень. Если публикация отклонена, живой бой не получает ни частичного XP, ни частичного исхода. Открытие итогов ничего не начисляет.

Практика остаётся у соответствующего тела, в том числе погибшего; новое воплощение её не наследует. Покупки узлов остаются отдельным действием вне боя. Лагерные упражнения продолжают повышать навык сразу.

## Реализация и совместимость

Новый бой основной кампании получает явную настройку `growth_timing = sm2.growth.after_battle.1` в setup; `Sm2TacticalBattle.start` проверяет её и допускает только при наличии развития и исходного мира. `Sm2CheckpointSession._prepare` добавляет настройку только для новых стартов; восстановление читает уже сохранённый боевой режим.

`Sm2BattleDevelopment` сериализует необязательное поле `growth_timing` с этой точной версией. Без него действует прежняя механика. Старые уже начатые бои и исторические примеры продолжают по прежним правилам; после завершения старого боя следующая встреча основной кампании использует новое правило. Старые снимки не переписываются при чтении.

Накопленные суммы `pending` не являются вторым файловым балансом: они восстанавливаются из уже сохраняемых счётчиков способностей и каталога наград. Пока бой активен, декодер требует точного начального XP/оплаты/узлов тела. В закрытом снимке требует начальный XP плюс полный прирост по счётчикам. Проверяются пределы XP с учётом ожидающей практики, общее число действий и прежние ограничения доступности способностей. Неизвестная версия и лишние поля отклоняются.

`settle_practice` переносит суммы в тело на закрывающей команде; повторный вызов без ожидающей практики ничего не начисляет. Полные проверки загружаемых файлов, прежние схемы внешних оболочек, архив и `.bak` сохранены. Новое поле версии вложенного правила делает снимки новых боёв несовместимыми со старой исполняемой сборкой; новая сборка читает оба варианта.

Точное совпадение неизменного тела позволяет использовать прежний ограниченный кэш проверенного развития вместо приростной проверки после каждого удара. Это ещё не компактный предварительно вычисленный профиль всех параметров: копирование состояния и часть запросов/проверок остаются. Гарантия конкретного ускорения не заявляется.

## Представление и проверка

Боевой журнал различает накопление и итоговое применение. Обзор развития показывает текущие зафиксированные уровни и отдельно XP после боя. Экран итогов автоматически открывается прежним маршрутом; внутри карточек участников таблица «Направление / Опыт / До боя / После боя», повышение выделено цветом и стрелкой. Источник данных — прежняя отделённая модель итогов, сравнивающая исходное и закрытое тело.

Новый набор `after_battle` проверяет реальные пси-удары через порог двух направлений, неизменную силу следующего удара, сохранение активного боя, отрицательные снимки, лимит XP, полные бои и отступление, рост на выходе, ранние снимки и старый активный бой. UI `battle_results` теперь проходит первый сценарий на основной checkpoint-кампании с новым правилом, а второй сохраняет проверку старого отступления. Нагрузочный инструмент ожидает новые события накопления и применения, поэтому прежнее побайтовое сравнение исходов до/после не является критерием: пользователь явно изменил момент влияния роста на бой.
