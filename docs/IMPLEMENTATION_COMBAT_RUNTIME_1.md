# Combat Runtime 1 — стоимость обычного боевого действия

13 сентября 2026. **0.8.26-combat-runtime.1**. Продолжение этапа 3 после Development 3 по подтверждению пользователя. Правила боя, развитие, игровые каталоги, форматы снимков и слоты остаются прежними.

## Граница работы

Разделить затраты на копию мира/сессии, проверку снимка, расчёт команды и представление. Убрать повторное восстановление неизменных данных из обычного действия. Проверить точное совпадение исходов и загрузку активного боя. Ориентир для обычного шага большого тестового тела — 100–200 мс без анимации; это цель измерений, а не гарантированная характеристика игры.

## Устройство

`Sm2LifeWorld` принимает явный внутренний `shared_content`; `Sm2JourneyWorld.copy_world` использует его. Ранее конструктор родителя заново строил каталог развития даже при создании внутреннего кандидата. Изменяемые тела, практика, ткани, вещи и состояния копируются отдельно. Внешние конструкторы по умолчанию сохраняют защитное построение каталогов.

`Sm2TacticalBattle.copy`, `Sm2TacticalSession.copy` и `Sm2BattleRunner.copy` копируют текущее состояние в памяти: очередь, RNG, ресурсы, анатомию, прогрессию, счётчики ИИ и признак записи исхода. Неизменные определения общие. `Sm2CheckpointSession._copy` больше не сериализует и не декодирует весь бой ради каждой команды. История кандидата также копируется глубоко.

В `Sm2JourneySession` введён внутренний `_commit_battle_action`. Обычная реализация по-прежнему вызывает полный `_publish`. Для checkpoint после принятой команды на изолированном кандидате проверяются источник копии через `WeakRef`, исходная ревизия, увеличение ревизии ровно на один, привязка встречи и ограничения размера снимка. Пока бой продолжается, мир лагеря заморожен; изменяется только его ревизия. Поэтому повторная полная проверка мира и повторный `restore` боя не выполняются. При завершении боя, лагерных действиях и общей публикации сохраняется полный путь проверки. Этот метод предназначен только для кандидата, созданного координатором, а не для входящего снимка или произвольного вызывающего кода.

Само боевое ядро по-прежнему декодирует и проверяет результат команды **до** принятия. Отказы, включая поздний отказ ограничения вместимости снимка, не публикуют частичный результат.

`Sm2ProgressDecodeCache` хранит не более восьми полностью проверенных значений развития. Совпадение требует fingerprint каталога, точного равенства всего значения и типов вложенных значений. Это исключает подмену числового XP булевым значением или обычного массива упакованным. Изменение XP, оплаты, узлов или каталога требует полной проверки; удачный результат возвращается отдельной копией. Кэш общий только для внутренних копий данного боя, не сохраняется и не является игровым состоянием. Все проверки связи практики со счётчиками атак, источником боя, ресурсами и анатомией остаются на каждом декодировании.

`status()` в боевом ядре/сессии/runner выдаёт небольшую отделённую проекцию очереди и управления. Внутренняя проверка очередного хода больше не строит полный интерфейсный `view()` со способностями и развитием. Публичный боевой обзор для UI сохраняется.

## Проверка

- `tools/check_combat_runtime.ps1`: отдельный runtime внутри проекта, профиль 200 направлений/10000 определений и 9985 синтетически изученных узлов плюс реально купленный пси-импульс. Фиксированный ID мира/seed, начальный и конечный снимки, события/хеш после каждого шага. Отдельные измерения ядра, копирования, представления, проверки вместимости, сохранения/загрузки. Существующий отчёт не перезаписывается.
- `combat_runtime`: ограниченный кэш и повреждённые значения, отсутствие общих изменяемых состояний, чужой/устаревший кандидат, отказ после принятия ядром, полный бой против прежнего координатора с полной проверкой, сохранение/загрузка между действиями и сравнение всех хешей.
- Регрессии развития, псионики/гибридов, ИИ, последствий, сохранений и UI — фактический состав и результат в [STATUS_COMBAT_RUNTIME_1.md](STATUS_COMBAT_RUNTIME_1.md).

## Оставшиеся границы

Проверка структурного бюджета всё ещё обходит полный снимок. Начало и завершение большого боя, полная проверка входящих сохранений/архива и изменение развития при начислении практики требуют дополнительной работы. Размер кэша ограничен; повторная проверка после вытеснения штатна. Тестовый каталог не является готовым контентом или приёмкой большой кампании. Паузы при сохранении нельзя скрывать отключением проверки повреждений.

Новые механики и визуальный этап не входят в этот срез. Перед этапом 5 остаётся обязательный ручной просмотр пользователя; коммит и публикация — по отдельному запросу.
