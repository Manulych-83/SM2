# M2.4 — последствия и исход

Пользователь согласовал продолжение командой «делаем». Реализуем §§5.3, 8 и соответствующие части §10 COMBAT_RULES_M2. ИИ обычного боя3×3 остаётся M2.5, окно поля — M3. Числа прототипа не меняются.

Тот же Sm2TacticalBattle(catalog,combat,consequences=true); без третьего аргумента сохраняется M2.3. Смежные части выделяются в Sm2DepartureResolver, Sm2MoraleResolver, Sm2BattleOutcome и Sm2RetreatPolicy. Sm2AttackResolver использует общий алгоритм для обычного удара и реакции; никакой второй формулы урона. Sm2BattleDice ограничивает счётчик RNG для любых бросков.

Команда: полная предварительная проверка → кандидат → затраты → атака/реакции/мораль → исход → передача активации при необходимости → одна ревизия → проверка снимка → публикация. Неверные команды и техническое исчерпание счётчика сохраняют старый снимок целиком. Accepted movement_interrupted сохраняет потраченные ресурсы и броски.

Реакция: один заряд и5 усталости, без AP; обычная ближняя damage-способность одноручного оружия (при нескольких — первая по ID). Реагирующие враги идут по числовому ID, доступность перепроверяется перед каждым ударом. Первое попадание останавливает шаг/escape даже при0HP урона. Вход в зону не реагирует, любой выход из контролируемой текущей клетки реагирует. Никаких рекурсивных реакций.

Мораль: один Sm2ConsequenceContext на верхнюю команду хранит уже проверенных получателей и очередь фактов. После попадания проверяется выжившая цель от потери≥ceil(hp_max/5) с P10 либо союзники смерти с P20; от первого fleeing — союзники с P10. Радиус4, получатели по ID, новые факты в конец. Иммунные, мёртвые, ушедшие и already-fleeing не бросают. M=clamp(resolve−P−5max(E−1,0),5,95). Не более одного броска на участника за команду; мораль только ухудшается. Внутри раунда I фиксирована по round_morale, фактическая мораль может быть хуже. Fleeing снимает wall, но сохраняет AP, владельца и сторону.

Escape с граничной клетки стоит2AP/4 усталости, вызывает реакции; успех меняет on_field=false, сохраняет HP, очищает AP/реакции/wall и очередь. Победа проверяется до нового раунда: живые на поле только одной стороны → opposition_removed; ни одной → mutual_removal; обе стороны сохраняют участие даже при fleeing; round_limit — после исчерпания последнего раунда. Исход содержит исходных участников, победителя либо null, погибших и вышедших. Никаких наград.

RetreatPolicy читает отделённый view. Поиск один раз обходит стратегические пути к границе с лимитом работы, учитывая полную стоимость маршрута+escape, затем усталость, координаты и маршрут. При отсутствии пути/ресурса — end_turn. Каждое решение — одна обычная команда; Session.advance_retreat выполняет один шаг текущего fleeing-участника. Никаких автоматических невидимых циклов внутри execute/load. На следующем решении путь пересчитывается; будущий драйвер ИИ M2.5 будет вызывать тот же механизм. Для лучника без стрел политика доступна будущему ИИ как явный запрос отхода.

Новая версия snapshot schema4/ruleset sm2.m2.consequences.1, winner:null/String. Все версии используют общий decoder с явными инвариантами своего режима, без подстановки фиктивных флагов. Старые schema2/3 в новый режим не мигрируются. Снимок содержит устойчивое состояние без незавершённой очереди фактов. Session format sm2.session.m2.consequences.1 добавляет result_recorded; record_outcome фиксирует только собственный законченный исход один раз, без экономики, и сохраняет этот флаг. Новый бой нельзя начать вместо ещё не записанного законченного результата.

Приёмка: реакции hit/miss/0HP/смерть/порядок/ресурсы/escape; мораль порог11/12 приHP60, M/M+1, цепи/радиус/иммунитет/одна проверка; бегство с новым маршрутом, без пути/ресурса, через несколько раундов; исход и однократная запись; все границы save/load, ошибочные снимки и RNG-ceiling rollback. Сначала чистый импорт, затем проверки, общий all и CLI. Сохранения пользователя не трогать. Все файлы/журналы/RuntimeRoot только E:\GPT\SM2.
