# M2.5 — ИИ и воспроизводимый бой 3 на 3

Пользователь согласовал этап командой «делаем» после M2.4. Объём: §9 и воспроизводимость §10 COMBAT_RULES_M2. Реализуется полный бой на существующей авторской карте с шестью участниками; окно поля и управление мышью остаются M3. Баланс и состав не меняются.

## Разделение ответственности

- Sm2AiProfile — проверенные данные политики sm2.ai.greedy.1: веса HP4/брони1, порог щита16, предел16 попыток на непрерывную часть активации, предел200000 единиц перебора. Resource content/m2/ai/default.tres загружается Sm2AiContentLoader. Неподдерживаемая политика и неверные поля отклоняются атомарно; параметры и fingerprint отделены от живого состояния.
- Sm2AiQueries — отделённая проекция участников/поля для общих боевых запросов. Настоящие RNG, ревизия и источник ID в неё не копируются. Для предполагаемой позиции переставляется только участник в проекции; прежняя клетка не сохраняет второго стрелка. Sm2AttackResolver.preview с position_only пропускает цену и случайность и проверяет общие позиционные условия; обычный режим по-прежнему проверяет всё. Расчёт урона у ИИ отсутствует.
- Sm2TacticalAi получает view, запросы и профиль. Возвращает одну команду с причиной выбора и, при необходимости, оценкой/маршрутом. Порядок: отход при fleeing/пустом луке; разрушение доступного активного или достаточно повреждённого щита; максимальная оценка обычной атаки; защита щитом при невозможности оплатить атаку; сближение, только если атаки нет по положению; иначе end_turn. Равенства разрешаются правилами §9, без случайности и Wait.
- Общий Sm2SpatialQueries расширен стратегическим поиском с риском. Риск — число шагов, уходящих из клетки, контролируемой врагом с доступной реакцией в наблюдаемом состоянии. Это оценка текущих угроз, без проигрывания будущих зарядов или бросков. Сначала минимизируется риск, затем AP, усталость, ID цели, координаты и числовой маршрут; при полном равенстве — ID способности. На каждой новой команде всё пересчитывается. Отдельный шаг ограничен максимальными ресурсами, весь путь может идти несколько раундов. Исчерпание лимита поиска/перебора — ошибка, не отсутствие пути и не ничья.
- Sm2BattleRunner — прикладной исполнитель над прежней TacticalSession. По умолчанию останавливается на controller=player; controller=ai и fleeing выполняются автоматически по одному step. Режим self_play=true явно разрешает диагностическое управление обеими сторонами. Постоянные владельцы и контроллеры бойцов не меняются. execute_player передаёт разрешённую пользовательскую команду в ту же сессию.

При отказе команды исполнитель перечитывает состояние и решает ещё один раз. Второй отказ или предел попыток останавливает его с диагностикой. Ошибка не подменяется end_turn или игровым исходом. Разрешение следующей команды происходит только явным вызовом step. run_to_end имеет отдельный предел команд; его достижение возвращает технический отказ с уже выполненной историей, сохраняет незавершённый бой и не записывает ложный результат.

## Сохранение и журнал

Снимок ядра остаётся schema4/sm2.m2.consequences.1; формулы и совместимость M2.4 не изменены. Новый внешний payload sm2.ai_run.1 хранит fingerprint профиля, режим self_play, прежнюю сессию, ключ текущей активации, число попыток и диагностическую ошибку. Ключ определяется battle_id/round/phase/active_actor_id; после смены активации счётчик сбрасывается. Restore проверяет режим, профиль, поля и согласованность активации, восстанавливает кандидата без выполнения решений. Профиль должен быть доступен в исходной версии — изменение данных/версии обнаруживается по fingerprint, миграция не делается автоматически.

Слот исполнителя m2_ai_run отделён от session (M1) и m2_prototype (шаговая M2). RuntimeRoot проверок/диагностики отдельный внутри проекта. Завершённый результат записывается существующим record_outcome один раз; повторный step после завершения возвращает already_recorded.

Журнал содержит точную команду, выбор ИИ, код принятия, события и число повторных попыток. ID/ревизии записываются десятичными строками. Sm2BattleReplay восстанавливает исходную сессию и выполняет записанные команды без вызова ИИ; после каждой команды сверяет код и события, при расхождении возвращает индекс ошибки. Это отдельная проверка от нового запуска ИИ с тем же seed.

## Приёмка

Сначала импорт чистой копии, затем m2_ai и весь all. Проверяются данные профиля, допустимые команды и их приоритеты, общая оценка, tie по ID, отсутствие зависимости от будущего RNG, позиционное планирование без двойника стрелка, безопасный маршрут, нехватка ресурса, лимиты/повтор отказа/сохранение ошибки, ожидание игрока, сохранение в середине боя и кандидатный restore. Результаты командного воспроизведения и повторного решения ИИ сравниваются отдельно.

CLI tools/run_battle_demo.ps1 использует настоящую карту и экипировку, seed20260909/1/76. Для каждого боя после12 команд — реальная запись/загрузка; затем полный бой до исхода, повтор с начала и повтор записанного журнала. Отчёт хранит setup, профиль, initial/saved/reloaded/final и все команды/события. Сохранения игрока не используются. Фактические числа и ограничения — STATUS_M2_5.md; окно и EXE в этот этап не входят.
