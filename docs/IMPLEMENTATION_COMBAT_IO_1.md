# Combat IO 1 — подготовка, завершение и хранение боя

13 сентября 2026. **0.8.27-combat-io.1**. Пользователь подтвердил следующий технический шаг после Combat Runtime 1: измерить атаки с практикой и ускорить завершение/сохранение. Игровые правила, схемы и контент прежние.

## Изменения

1. `Sm2DevelopmentCatalog.build` имеет необязательный внутренний `shared_progression=false`. Фабрика встречи явно передаёт построенный неизменный каталог с `true`, продолжая проверять все связи развития, псионики, улучшений и нового боевого снаряжения. По умолчанию каталог копируется; публичный `progression()` также сохраняет защитную копию. В подготовке runner получает уже построенные каталоги встречи через существующий `shared_content`.
2. `state_copy()` на границе Battle → Session → Runner возвращает отдельную копию принятого ядром состояния. `_check_battle` сначала по-прежнему полностью восстанавливает входящий payload, затем проверяет соответствие сценарию, полю, участникам и квитанции на копии этого результата. Второго декодирования того же боевого снимка нет. Неуспешный `restore` не даёт права продолжать проверки или применять состояние.
3. Построение итогов использует общий неизменный каталог и локальный ограниченный кэш развития: исходное тело, уже проверенное при чтении исхода, не декодируется повторно ради вычисления разницы XP. Поведение самого кэша прежнее: точное значение, типы и fingerprint, полная проверка любого изменённого значения.
4. Короткий заголовок журнала получается из фактического исхода через `title_for`, общего с экраном итогов. Для одного заголовка больше не строятся карточки практики, анатомии и инвентаря. Факты похода по-прежнему получают полный фактический результат.
5. Проверка возможности записать исход использует компактный `status`, а не интерфейсный обзор.

Общий `_publish`, проверка мира, ограничения файлов/структуры, проверка архива, старого primary и `.bak` остаются. Сохранение не доверяет произвольному входному словарю. Нового постоянного кэша сохранений нет.

## Стенд

`tools/check_combat_io.ps1` запускает полный бой 10000 определений / 200 направлений / 9985 тестовых узлов плюс реально изученный пси-импульс. Игровой ID мира и seed фиксированы. Команды героя выбираются тем же детерминированным планировщиком через обычный игроковый вход; ИИ шагает своим входом. Проверяются реальные попадания, промахи и практика; состояние хешируется после каждой команды.

После седьмого действия выполняются сохранение, повторное сохранение существующего файла и загрузка. Используется **Sm2CampaignStore**, как у основной игры, с валидатором большого тестового контента. Это существенно: повторная запись проверяет и предыдущий primary, поэтому её время нельзя подменять замером первого сохранения в пустой слот. После боя отдельно измеряются итоговый экран, сохранение и загрузка завершённого мира.

Новый набор `combat_io` проверяет изоляцию возвращённого состояния, отказы повреждённых боевых данных, прежнюю защиту публичных каталогов, валидацию связей при совместном использовании, одинаковые fingerprints, заголовки исходов и сохранение итогов. Полный состав регрессий и цифры — в [STATUS_COMBAT_IO_1.md](STATUS_COMBAT_IO_1.md).

## Ограничения

Атака с практикой всё ещё требует полной проверки изменённого развития. Повторная проверка мира/структурного бюджета при публикации, проверка архива и предыдущего файла также остаются затратными. Этот срез не объявляет достигнутой готовность большого мира и не меняет механики ради скорости.

Перед этапом 5 обязателен ручной просмотр пользователя. Новые механики, коммит и публикация сюда не входят.
