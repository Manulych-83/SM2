Большой профиль — 200 направлений, 10000 определений узлов и искусственно развитое тело; это нагрузочные данные, не готовая большая кампания.

Медиана сохранения **7212 → 6861 мс**, загрузки **3315 → 3087 мс**; каждый снимок совпадает. Выигрыш здесь умеренный, пауза около семи секунд остаётся. Главный результат — ускорение атак с практикой на большом дереве.

## Проверки

**3278 проверок ядра и 847 проверок интерфейса прошли, коды выхода 0.** [Сводка с отдельными отчётами](../outputs/validation-1/checks.json).

- Новый набор `validation`: 68 проверок. Сравнение с полным декодером, неверные типы и значения XP/оплаты/ID/узлов, смена каталога, изоляция и предел кэша, входящие повреждения, атомарность позднего отказа по структурному бюджету.
- Регрессия: combat_runtime, combat_io, checkpoint, development_scale, p2_development, p5_hybrids, p5_shield, p5_growth, p5_cross_nodes, m2_ai, survival_tissues, campaigns, expedition, battle_results, integration.
- Интерфейс с настоящим рендером: combat_hud, battle_results, campaigns, expedition. Полный поход, доставка четырёх нужных экземпляров, итог, загрузка и смена тела проверяются существующими сценариями. Скриншот развития из сборки просмотрен; новых визуальных изменений в этом срезе нет.
- При разработке отрицательная проверка выявила ошибку сравнения PackedStringArray с Array; проверка типа перенесена перед сравнением, финальные 68 проверок проходят. Первый обычный нагрузочный запуск также остановился из-за ссылки стенда на отсутствующее синтетическое направление: искусственное начисление теперь только в большом профиле. Неудачные запуски не включены в итог.

Команды воспроизведения: `tools/run_checks.ps1 -Suite validation`; те же наборы регрессии через `-Suite`; `tools/run_ui_checks.ps1` с четырьмя указанными наборами; `tools/check_combat_io.ps1 -Ordinary` и без флага. Все используют отдельный `-RuntimeRoot` внутри `.local/validation-1`; результаты профилей — внутри `outputs/validation-1`.
