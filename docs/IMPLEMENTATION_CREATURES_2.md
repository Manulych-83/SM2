# Creatures 2 — шаблоны в основном походе

13 сентября 2026. **0.8.37-creatures.2**. Согласованный рабочий срез: типы противников → постоянные тела/вещи → бой с тканями → последствия → сохранение. Это продолжение этапа 3; ручной просмотр пользователя перед этапом 5 остаётся обязательным.

## Поведение

Новая основная кампания использует `content/packages/world_creatures.json` и `content/creatures/world.json`. Четыре человеческих типа: страж руин, налётчик, следопыт и отравитель. Шесть постоянных противников привязаны к типам через ID тел. В первой встрече два стража имеют прежние параметры/снаряжение; затем встречаются налётчик со следопытом и страж с отравителем. Первые числа сохранены, но новая кампания использует общий ИИ способностей; идентичность исходов со старым ИИ не обещается.

Для нового типа в рамках поддержанной семантики достаточно данных: профиль очереди/боя, снаряжение, действия со статусами, иммунитеты/сопротивления и привязка существующего тела. Код не ветвится по названию врага. Новые физические предметы также должны быть объявлены в каталоге предметов; неизвестная операция не становится механикой от одной записи JSON.

## Архитектура

- `Sm2CreatureCatalog.TYPES_VERSION = sm2.creature_types.1` явно разрешает каталог определений без самостоятельных встреч. Историческая `sm2.creatures.1` сохраняет прежние требования и fingerprint. Полные проверки существующих профилей/экипировки/эффектов переиспользованы.
- `Sm2WorldCreatureContentLoader` строит новый профиль поверх неизменённого Survival 3. `Sm2WorldCreatureCatalog` проверяет полную привязку всех противников трёх встреч, ID, ссылки, физическое снаряжение и совместимость анатомии. Ошибка не публикует частично построенный каталог; публичные запросы отдают копии.
- `JourneyWorld.start` создаёт реальные предметы из типа, с отдельным ID для каждого экземпляра. Прочность/боеприпасы/место принадлежат вещи, а не шаблону. Герой и спутник получают прежний стартовый комплект и свои модели развития.
- `EncounterFactory` берёт фактически экипированные предметы из мира, добавляет только профили участвующих противников, компилирует их эффекты и сохраняет псионические способности героя. Расходы, ИИ, урон, ранения и исходы идут через общее ядро.
- HP в человеческом шаблоне обязаны быть 60, как у проекции действующей анатомии. Это не новое самостоятельное здоровье: ткани/органы/кровь определяют состояние и смерть. Другой максимум сейчас отклоняется, вместо рассогласования с анатомией.
- Новые имена противников — отделённые данные представления в `BattleRunner`; не меняют снимок симуляции, копируются с исполнителем и восстанавливаются из проверенных определений. Подписи героя/спутника прежние. Новых графических ресурсов нет. Боевые статусы действуют по прежним правилам встречи; оставшаяся длительность статуса не переносится в следующий бой, анатомические повреждения сохраняются.

## Сохранения и совместимость

Новый мир явно пишет `sm2.world.creatures.1` и неизменную секцию `creatures` с версией/отпечатком/привязками. Обёртка `sm2.checkpoint_journey.1`, анатомические состояния, физический инвентарь и архив прежние. Декодер сверяет весь мир с выбранным доверенным профилем; файл не назначает себе политику валидации. Подмена ID типа, версии, отпечатка, лишние/пропавшие поля и расхождение HP/анатомии отклоняются.

`Sm2Campaigns` держит новый и прежний профили. По отпечатку выбираются соответствующие определения и прежний/новый ИИ, затем выполняется полная проверка. Старые Survival 3 и checkpoint-кампании продолжаются без замены мира или противников; старый активный бой не шагает при открытии. Новые пустые слоты выбирают новый профиль. В одном меню могут находиться старые и новые кампании, резервные копии сохраняют прежнюю проверку.

При открытии возвращается уже проверенный исполнитель соответствующей версии с закреплённым физическим слотом. Если файл живой сессии был заменён кампанией другой версии, локальная кнопка загрузки отказывает и предлагает открыть её через меню, а не подменяет мир при сохранении старых определений.

Автоматической миграции старого мира на шаблоны нет. Изменение авторского контента, даже неиспользуемого типа, меняет полный fingerprint нового профиля и требует совместимого набора данных или новой кампании. Это строгая совместимость двух известных профилей, не универсальная миграция контента.

## Проверки и границы

Итог: **2252 core + 435 UI = 2687 проверок**, все прошли; экспорт, проверка упакованных ресурсов и графический запуск EXE успешны. Основной экран просмотрен в 2560×1440 и 1280×720. Результаты: [сводка](../outputs/creatures-2/summary.json). Новый набор `world_creatures` проверяет реальные бои/продолжение, ткани и смерть, независимые вещи, восстановление вещи с трупа и её последующую загрузку, полный поход за четырьмя медикаментами, три встречи, применение эффекта отравителя, несовместимые определения и смешанные старые/новые слоты. Для сравнения JSON-снимков используется канонический хеш: JSON может представить целые числа как float. Автопроход использует решения ИИ как обычные команды игрока, не переключает записанный режим управления.

Один проверочный полный бой оставляет раненых/погибших; безопасный маршрут за медикаментами проверяется отдельно с настоящим отступлением. Отступление не выдаётся за победу. Лечение или исходы не подменялись для прохождения проверки.

Сохранены существующие три встречи 2×2, роли героя/спутника и размещение тел на карте. Привязки требуют уже объявленных противников; динамическое население, генерация тел из произвольных спавнов, нечеловеческая анатомия и переменные составы основного похода не реализованы. Самостоятельные демонстрационные встречи Creatures 1 по-прежнему поддерживают свои составы.

Базовые каталоги предметов/операций включаются в бой целиком; только новые профили противников выбираются адресно. Эта проверка не является совместной нагрузочной приёмкой 10000 предметов/5000 навыков/2000 статусов/3000 врагов или большого постоянного мира. Следующий пункт — проверка совместного масштаба в обозначенных границах, затем визуальная доводка.
