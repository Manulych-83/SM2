# M2.3 — атаки и экземпляры экипировки

Пользователь согласовал M2.3 командой «Делаем». Подэтап реализован, результаты — [STATUS_M2_3.md](STATUS_M2_3.md). Объём: разделы 6–7 COMBAT_RULES_M2, смерть и исключение из очередей, прогноз, предметные экземпляры и сохранение. Реакции отхода/проверки морали/бегство, ИИ и итог боя остаются следующими подэтапами; заданная входная мораль уже влияет на шанс. Обычная победа пока не определяется.

Расширяется существующий Sm2TacticalBattle, а не создаётся вторая копия очереди. Второй необязательный аргумент — Sm2CombatCatalog; без него прежний M2.2 и его тестовые контракты работают без изменения. Новый каталог связывает боевые характеристики и слоты с IDs профилей/экипировки Sm2TurnCatalog. Нагрузка берётся только из старого каталога. Валидация запрещает неизвестные операции, ссылки, слоты, дубли и двуручное оружие со щитом.

Sm2CombatProfile/Gear/Ability — типизированные определения; авторский Resource преобразуется в проверенный каталог. Профиль тела содержит участки с весами и множителями HP. Операции damage, shield_break, shieldwall реализованы явно. Действия доступны через способности экипировки, не через имена меча/лука в координаторе. Команда use_ability с ability_id и target_actor_id (для shieldwall — сам владелец).

Sm2Combatant хранит HP, экземпляры предметов, флаг использования shieldwall и эффект с ID источника и раундом окончания. Sm2CombatItem: отдельный item_id, definition_id, slot, current, ammo; владелец определяется содержащим участником. Выдача ID детерминированна по числовому actor_id, затем слотам weapon/shield/body/head. Во время M2.3 слоты не меняются. Разрушенный предмет остаётся в слоте и сохраняет нагрузку.

Sm2AttackResolver проверяет цель/дальность/LOS/высоту/ресурсы/стрелы и общие формулы. Preview не использует RNG; сообщает H, слагаемые, диапазоны по участкам и ожидание x100 с учётом промаха. Execute списывает цену, затем бросает hit; только при попадании zone и damage. Щитовая защита и разрушение щита бросков не делают. Формулы и порядок — §§6–7; смерть ровно один раз очищает очередь/AP/реакции/эффект.

Shieldwall действует до первого начала следующей активации: Wait не снимает, начало раунда только сбрасывает лимит применения. Смерть или сломанный щит снимают немедленно. Состояние fleeing запрещает атакующие действия и щитовую стойку. Лук запрещён при соседнем контролирующем враге, требует LOS и дистанцию2–6; ближайшие угрозы/окружение используют одно определение наличия ближнего оружия, доступности и перепада высоты≤1.

Для запрета стрельбы дополнительно требуются одноручное оружие, заряд реакции и запас5 усталости у контролёра; для окружения эти два ресурса не требуются. Сами реакции отхода здесь не исполняются. Preview сообщает только реализованные угрозы стрельбе; риск остановки движения появится с M2.4.

Боевой snapshot schema3/ruleset sm2.m2.attacks.1 дополняет очередь combat_fingerprint/next_item_id и actor.combat. Sm2CombatSnapshot сначала проверяет точную внешнюю схему, проверяет очередь существующим decoder, затем HP/предметы/ссылки/эффект. Никакой загрузки через start и выдачи новых ресурсов. M2.2 schema2 остаётся прежним режимом; автоматической миграции нет. Прикладной payload sm2.session.m2.attacks.1, слот m2_prototype; загрузка несовместимого режима отклоняется, файл не переписывается.

Проверки: формулы из примеров B–E; H/H+1, 5/95, body/head, броня0/равнаD/толщеD, ограничение текущимHP; сохранение RNG при preview/reject, miss только hitdraw; настоящие melee/ranged/shieldwall/breakshield/kill; Wait и следующий раунд с активной щитовой защитой; JSON+дисковое сохранение и повтор продолжения; отрицательные входы/предметные ссылки. Затем полный all на чистом импорте и изолированный диагностический прогон. Все материалы внутри E:\GPT\SM2, UI/EXE здесь не принимаются.

Авторский каталог — content/m2/combat/catalog.tres (Sm2CombatContentManifest); Sm2CombatContentLoader.load_scenario возвращает {ok,catalog:Sm2TurnCatalog,combat:Sm2CombatCatalog,setup,errors}. Аргумент2 Sm2TacticalBattle и аргумент3 Sm2TacticalSession — этот combat. Модель чтения дополняется actor.combat, hp_max и abilities; снимок сохраняет ID как строки. Способности shieldwall доступны только при целом щите; полный preview отдельно проверяет ресурсы, цель и мораль.

Защитные пределы: до10000 определений в группе, HP/характеристики/прочность/боезапас≤10000, параметры способности≤1000 (проникновение≤100%, дальность≤64). Поддержаны зоны head/body с положительными весами в сумме100 и множителемHP≤1000%. Новые названия операций или зон требуют реализации и тестов, а не только строки в каталоге. Кандидатная валидация применяется и после частично выполненного разрешения: исчерпание большого счётчика RNG откатывает команду целиком вместе с затратами и бросками.
