# Runtime 2 — оптимизация измеренных операций

13 сентября 2026. Пользователь подтвердил ограниченный этап оптимизации до расширения контента. Версия **0.8.24-runtime.2**. Игровые механики, числа, форматы сохранений и лимиты не меняются.

## Выполнено

1. `Sm2CampaignStore.checked` может передать восстановленную проверяющим кодом сессию. `Sm2CheckpointSession.load_game` принимает её через публикацию кандидата; повторное восстановление архива/боевого контекста устранено. Пользовательский файл и живой мир не изменяются при отказе. Общие хранилища с иными валидаторами сохраняют прежний путь.
2. Меню через `Sm2Campaigns._preview` читает конверт и проверяет текущий мир, без восстановления истории/боя. Полная проверка и выбор пригодной `.bak` происходят при загрузке выбранной кампании. UI прямо сообщает «Полная проверка — при загрузке». Предпросмотр не является свидетельством пригодности непрочитанного архива; повреждение только исторического блока может обнаружиться после нажатия «Загрузить».
3. `Sm2CheckpointArchive.blocks` содержит только ещё не опубликованные блоки. После их успешной записи ссылки обслуживает репозиторий; следующие сохранения не сериализуют повторно каждый старый блок в цикле публикации. Общая проверка целостности существующих блоков при семантической проверке сохранения/загрузки остаётся. Если запись корня отказала, опубликованные блоки остаются доступными по прежним ссылкам; повтор безопасен.
4. `Sm2CheckpointArchive.page` читает только блоки, пересекающиеся с диапазоном страницы. `Sm2JournalQuery` выдаёт UI не более 30 строк. Поиск/фильтр сканирует ограниченные страницы один раз на запрос и ревизию, затем использует совпадения. Старые Journey-профили сохраняют прежнее восстановление фактов. Диагностический `Sm2JournalView.build` всё ещё может запрашивать весь журнал.
5. Внутренние кандидаты Checkpoint используют уже построенные каталоги своей сессии. Внешнее создание сессии по умолчанию сохраняет защитное копирование/построение каталогов. Состояние тела, инвентарь, прогрессия и мир продолжают копироваться отдельно. Изменение кандидата не изменяет исходную сессию.
6. Проверка инвентаря агрегирует массу/объём содержимого за один проход. Сортировка ID выполняется один раз; определения предметов повторно используются внутри одной проверки. Прежние проверки ссылок, мест, размеров, слотов, запрета вложенных контейнеров и вместимости сохранены. Устранён повтор полного обхода/сортировки предметов для каждого контейнера.

## Границы

- Полный архив по-прежнему проверяется при загрузке выбранной кампании. Это сохраняет обнаружение повреждений и прежний откат к пригодной `.bak`. Стоимость холодной загрузки остаётся зависимой от истории; фоновая проверка/частичная загрузка без полного архива не введена.
- Кэш репозитория хранит прочитанные блоки, проверяя SHA256 всего файла при повторном обращении. Постраничный API ограничивает запрос/копирование для UI, но не означает ограниченного общего объёма кэша после полной загрузки.
- Поиск по всему журналу требует сканирования; широкий фильтр хранит много совпадений. Индекс полнотекстового поиска и ограниченный кэш — дальнейшая работа.
- Сохранение записывает только новые блоки, но проверки целостности старого и нового снимков остаются. Постоянная стоимость сохранения при любой длине истории не обещается.
- Копирование/проверка всего текущего мира пока сохранены. Замеры копирования текущего мира ~2 мс не обосновали рискованную замену транзакционной модели в этом этапе. Повторное построение каталогов и квадратичная проверка контейнеров устранены отдельно.
- Нагрузочный инвентарь и тело с 1000 изученными узлами — отдельные корректные domain-fixtures. Они не объявляются пригодной кампанией с таким количеством вещей, полностью готовым UI или итоговым балансом.

Все файлы и проверочные среды внутри `E:\GPT\SM2`. Существующие пользовательские слоты не используются. Коммит/публикация отдельно; до этапа 5 сохраняется ручной просмотр пользователя.
