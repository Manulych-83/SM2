# SM2 — действующие правила

## Начало задачи

- Рабочая папка: `E:\GPT\SM2`. Все создаваемые файлы, логи, runtime и сборки держать внутри неё. Другие проекты читать только по необходимости; не менять.
- Сначала проверить `git status --short`, прочитать `docs/CURRENT_STATE.md`. Затем читать только контракт затронутой системы и нужные участки кода.
- Здесь только постоянные правила. Не дописывать сюда хронику выпусков. Текущий статус обновлять в одном месте; старые решения искать адресно через `rg`.
- Полная прежняя редакция инструкций сохранена в `docs/archive/AGENTS_BEFORE_WORKFLOW_1.md`. Это историческая справка, не список актуальных следующих этапов. Не читать её целиком при каждой задаче.

## Границы согласования

- Выполнять согласованный этап до рабочего результата. Предложения, открытые вопросы и синтетические примеры не объявлять принятыми игровыми правилами.
- **Перед этапом 5 текущего плана** пользователь вручную смотрит игру и основные экраны; получить обратную связь и согласовать правки/продолжение. Отсутствие замечаний не заменяет просмотр. Это не исторические P5/UI 5.
- Новые механики, удаление поддержки сохранений, коммит и публикация — по отдельному запросу пользователя. Не трогать чужие незавершённые изменения.
- Субагенты — только по явному запросу; обычные задачи вести в текущем чате.

## Архитектура и сохранения

- Godot 4.7.2, GDScript. `content/` — определения; `src/domain/` — правила; `src/application/` — команды/запросы; `src/infrastructure/` — хранение; `src/presentation/` — интерфейс.
- Домен независим от сцен, кадров, часов ОС и глобального RNG. Внешнее состояние полностью валидируется. Команды атомарны; интерфейс использует прежние команды и проверку ревизии.
- Каталоги общие и неизменяемые внутри доверенного исполнения; публичные границы сохраняют защитные копии. Не подменять это доверием к файлу или хешу.
- Новые предметы/навыки/эффекты/существа задавать данными в рамках существующих операций. Новая семантика требует правил, валидации и проверки поведения.
- Не менять старые версии, fingerprint, слоты и правила восстановления неявно. Основной поход — checkpoint; архив истории и текущий мир разделены. Старые профили поддерживаются отдельно.
- Рост героя/спутника в новых боях основной кампании применяется после боя; во время боя копится практика. Старые активные бои завершаются по записанному режиму.
- Изолированные нагрузочные каталоги не означают готовность огромной кампании, полного UI или всех каталогов одновременно. Ограничения фиксировать явно.

## Интерфейс и запуск

- База: полный экран 2560×1440, KEEP, scale 1.6; логическая компоновка 1600×900. Не масштабировать повторно.
- Тёмные панели и тонкие бронзовые рамки; треугольные украшения не возвращать. Фигуры в полный рост, фиксированные позы/короткие движения; подробная анатомия на экране тела.
- Вместимость без пространственной сетки. Снаряжение/передача/тайник вне боя; перевязка также в бою.
- Обычное меню: «Продолжить» / «Новое воплощение», три слота, настройки и выход. Удаление слота только после двух отдельных подтверждений с проверкой неизменности файлов. Полное прежнее меню и все примеры доступны через `tools/run_game.ps1 -LegacyDemos`; код, слоты и проверки сохранены.
- Запуск Godot/EXE через `tools/find_godot.ps1` и существующие обёртки: APPDATA/LOCALAPPDATA/TEMP/TMP внутри `.local`. Пользовательские слоты не использовать для тестов.
- PowerShell с русским текстом сохранять UTF-8 **с BOM** для Windows PowerShell 5.1.

## Экономный рабочий цикл

- Карта проверок: `docs/TESTING_POLICY.md`. Запускать затронутые сценарии и проверки их связей; общие изменения требуют более широкого набора.
- После успешной проверки повторять её при новых изменениях, сбоях или нерешённом риске. Не создавать тесты, которые лишь повторяют реализацию простой правки.
- Сначала краткая сводка команды/отчёта; полный лог читать только при ошибке. Ограничивать поиски путём и диапазоном. Не выводить каталоги файлов и большие документы целиком.
- Полные промежуточные логи/скриншоты — в `.local`; итоговая проверяемая сводка и необходимые доказательства — в `outputs/<этап>/`. Не копировать одинаковые артефакты каждого успешного прогона.
- В финале: что готово, как проверено, существенные ограничения. Не обещать процент экономии токенов без измерения.
- Новый чат удобен на границе завершённого этапа: передать путь, текущий статус и конкретную задачу. Автоматически не создавать новый чат.
